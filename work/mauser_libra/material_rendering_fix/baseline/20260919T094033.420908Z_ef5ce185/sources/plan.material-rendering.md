## 1. 目标与范围

将当前 CS:GO Legacy 中毛瑟天秤座的枪身材质向用户提供的 CF 参考图靠拢：

- 金属呈明亮暖金／香槟金，避免整体暗橄榄色、棕黑色。
- 黑色主体保留暗色，同时具备清晰的金属亮边、纹样和反射层次。
- 高光与环境反射随视角连续变化，不成为固定在 UV 上的亮纹。
- 铭牌、圆形徽章、金色边框、黑色侧板分别保留细节和材质差异。
- 明处不过曝，暗处不整片发黑，也不依赖整枪自发光维持可见性。

用户已确认位置和 FOV 没问题。本计划只处理枪身材质和渲染。

不修改：位置、FOV、VIEW、模型轮廓、UV、骨骼、动画、手套、声音、attachment、地图和全局游戏画面设置。

默认保留现有材质槽和三角形分配。若实验确实证明需要调整材质分区，仅允许改变 material assignment，并验证几何、UV、权重和动画不变。

## 3. 现有证据与待证实事项

### 已确认的实现与报告事实

1. `source1_material_translator.py` 会根据低 diffuse 亮度选择 `matte_dark`。当前 r5 对应 1516／2767 个三角形，关闭 Phong 且没有 envmap；其 specular／环境遮罩并非全为零。
2. 环境反射除逐像素 Alpha.B 遮罩外，还受到区域平均 Alpha.B 和强度上限的影响。只有 r1、r4 保留 envmap。
3. SpecularMap 被转换为灰度遮罩，再用全图平均色生成统一 Phong tint，局部彩色高光信息因此丢失。
4. 参考渲染器与 Source-like 预览的高光公式、指数存在差异，不能用提高 boost 直接保证响应形状一致。
5. 五组离线比较中，Source-like 平均亮度约为 CF 参考的 22%–29%；H 阶段记录差异后仍成功退出，未设置视觉差异失败门槛。
6. 本轮独立只读核验时，当前磁盘 VPK 与 addon_v2 的 29 个文件 SHA-256 全部一致，其中枪身材质 9／9 一致。旧 `i_pak_verify.json` 早于最新部署，已过期。

### 尚未证实，不能作为实现前提

- CF 参考渲染器的公式仍包含 INFERRED／UNKNOWN，不能等同 CF 实机 shader 真值。
- 离线亮度比例不能直接当作游戏内亮度比例，也不能据此把整枪亮度乘以固定倍数。
- 当前磁盘包一致，不证明用户截图当时的进程加载路径、材质缓存和实际加载版本。
- 当前引擎分支下 Phong、envmap、normal alpha 等参数的实际组合响应，仍需游戏内实验。
- 单张 CF 截图不足以恢复全部环境、曝光、反射方向及原 shader 常量。

“转换中丢失了重要响应”是优先调查方向；各因素对当前截图的贡献大小由后续实验决定。

## 7. P1：单变量游戏实验

每项实验从基线或明确命名的父实验派生，不无意继承其他改动。先完成判因，再组合有效修正。

| ID | 问题 | 唯一改变的因素 | 观察与决策 |
|---|---|---|---|
| M1 | r5 是否被错误地当成无高光表面？ | 仅恢复 r5 的受遮罩控制的 Phong，其余槽与 envmap 不动 | 金纹／亮边是否出现，黑色主体是否仍保持暗色；无变化则先查遮罩和 shader 生效情况 |
| M2 | 当前 envmap 是否实际贡献可见反射？ | 仅关闭现有 r1／r4 envmap | 同场景同视角差图是否有响应；无响应不等于无需反射，先查环境采样和参数组合 |
| M3 | 区域平均遮罩是否压低了反射？ | 仅改变 envmap 的区域强度计算，保持逐像素遮罩与环境资源不变 | 比较亮度恢复、局部洗白和转向变化；使用有界强度实验，不直接认定取消上限就是正确答案 |
| M4 | 高光覆盖形状是否偏离目标？ | 固定遮罩、颜色和增益，仅改变指数；之后另批次单独改变增益 | 比较亮斑覆盖、边缘连续性和动态变化；不能只看峰值更亮 |
| M5 | 全局 tint 是否破坏局部金属色差？ | 在已确认有效的高光路径上，仅测试区域色彩策略 | 金框与黑色金属是否能同时接近目标；不以全枪染黄换取金色 |
| M6（条件触发） | 法线或遮罩约定是否阻止正确响应？ | 仅在前述实验异常时，分别测试平坦法线、诊断遮罩；每项独立 | 定位方向／通道问题；只有证据成立才修改正式编码约定 |

若引擎行为与预览不一致，优先以当前 CS:GO Legacy 实测定位参数组合；需要补充文档时核对适用引擎分支，不把其他 Source 游戏的行为直接视为已验证。

**退出条件**：每个采用的修正至少有可解释的 A/B 证据。没有生效证据的参数不能进入最终组合。

## 8. P2：选择最终材质方案

主代理根据 P1 结果作出以下决策：

### 8.1 材质分类

- 不再仅凭 diffuse 较暗就关闭金属响应。
- 同时检查 specular、环境遮罩、零件及 UV 内部混合情况。
- 优先用像素遮罩保留同一三角形中的暗底与金纹，不假设增加材质槽就能拆开三角形内部的纹样。
- 仅在现有槽无法表达必要色差且已有证据时，调整材质分区。

### 8.2 高光

- 对高光宽度、强度、颜色分别校准。
- 保留目标需要的金色和近中性亮边，避免全局统一暖色覆盖所有金属。
- 记录 Source 无法保留的逐像素彩色高光信息以及采用的近似，不声称完全等价。

### 8.3 环境反射

- 先纠正已验证的遮罩／衰减问题，再决定使用地图环境还是经过验证的专用反射资源。
- 若地图环境使材质跨场景严重偏色，才进入专用 cubemap 候选实验；必须验证面序、方向、颜色空间、mip 和视角响应。
- 不直接把原 LobbyCube 绑定后宣布恢复成功；原 CF 采样语义与 Source 反射采样的差异必须明确。
- 固定 UV 自发光或静态 cubemap 烘焙不能代替最终的动态金属反射。补光若确有必要，只能承担经过明／暗场景验证的有限底色可读性补偿。

### 8.4 参数归属

- 通用模块只保留有跨输入依据的转换规则。
- 毛瑟的拟合参数、参考区域和容差保存在武器本地配置中，标为视觉近似。
- 不为让报告通过而修改 CF 参考公式；参考语义修正必须有独立证据。

**退出条件**：得到一个可解释、可复现的组合候选；清楚列出保留、近似、丢失和未知项。

## 9. P3：修正预览与验收

1. Source-like 预览应读取实际候选材质参数，减少预览配置与产物脱节。
2. 将“数据有效／能够生成”“行为自洽”“接近目标外观”分别报告，不能共用一个 PASS。
3. 参考 shader 的 INFERRED／UNKNOWN 继续保留，不因测试通过自动升级为 OBSERVED。
4. 同场景同姿态实验使用区域统计：亮度中位数／分位数、金色偏色、黑色区域细节、高光覆盖、饱和裁切和视角变化。
5. P0 完成后、最终调参前，记录各区域的接受范围及依据。用户参考图与不同引擎场景不具备精确对应时，使用明确的人工视觉标准，不编造“相似度百分比”。
6. 明显的整体变暗、高光消失或黑色区域洗白必须记为 FAIL。原有 22%–29% 离线亮度保留比例作为回归警报，不能直接成为游戏内乘数。

### 最终运行时验收清单

- [ ] 徽章、金框、铭牌具备明亮暖金属层次，无大面积暗橄榄／棕黑观感。
- [ ] 黑色侧板仍黑，金纹与亮边清晰，没有整片灰白或统一自发光。
- [ ] 转向时高光和反射连续变化，不是固定 UV 亮纹。
- [ ] 明处不大面积饱和，暗处仍能辨认主要金属区域和纹样。
- [ ] 无鱼鳞状反射噪声、异常接缝、法线翻转或材质槽边界。
- [ ] 与基线相比，位置、FOV、UV、模型、骨骼及动画一致。
- [ ] 候选产物、部署包与运行时截图属于同一版本。
- [ ] 未解决的近似和引擎限制明确记录；用户确认外观后才标记视觉验收 PASS。

## 11. 暂停与回退条件

- 发现实验改变了范围外内容：回退该实验，重新限定写入范围。
- 运行时材质身份不明确：暂停视觉归因，先确认实际加载版本。
- 单变量实验没有产生预期响应：查参数支持、遮罩、资源路径及缓存，不连续堆叠 boost。
- 改善金色却导致黑色区域洗白、明处过曝或反射噪声：拒绝候选，回到对应因素。
- 只有固定 UV 发光才能逼近某一张截图：记录能力差异，重新选择方案，不作为动态金属效果验收通过。
- 需要自定义引擎 shader、注入或修改游戏二进制：超出本计划，另行评估，不自动实施。
